# Telegram Relay

Связка «клиенты в Telegram ↔ вы в почте»: сообщения от клиентов из любой страны
приходят вам письмами на Яндекс Почту, а ваши ответы на эти письма уходят им
через вашего же бота. Вы никогда не открываете Telegram лично — с Telegram
взаимодействует только автоматика в этом репозитории.

## Как работает

```
Клиент (за рубежом) → ваш Telegram-бот → relay.py poll → письмо вам
Вы отвечаете на письмо → relay.py answers → sendMessage клиенту через бота
```

- Скрипт работает в GitHub Actions по расписанию каждые 5 минут (публичный
  репозиторий = бесплатные минуты Actions без лимита).
- Верификация: новый пользователь, написавший боту лично, получает кнопку
  «Подтвердить телефон» (нативная кнопка Telegram). Подтвердившийся попадает
  в белый список `allowed.json` — хранятся только числовой ID и последние
  4 цифры телефона, тексты сообщений в репозиторий не попадают.
- Групповые чаты/каналы: перечислите их ID в секретной переменной
  `TELEGRAM_ALLOWED_CHATS` (через запятую) — без неё сообщения из групп игнорируются.
- Ответ: просто ответьте на письмо (кнопка «Ответить» в почтовом клиенте) —
  релей уберёт цитирование и отправит ваш текст клиенту (до 4000 символов,
  ограничение Telegram).

## Настройка (один раз, через веб-интерфейс GitHub)

1. **Пароль приложения Яндекс Почты.** Откройте id.yandex.ru → Безопасность →
   «Пароли приложений» → создайте пароль для почты. Это НЕ ваш обычный пароль —
   он нужен для программного доступа SMTP/IMAP.
2. **Секреты репозитория.** Settings → Secrets and variables → Actions →
   New repository secret — добавьте два:
   - `TELEGRAM_BOT_TOKEN` — токен вашего бота от @BotFather;
   - `MAIL_APP_PASSWORD` — пароль приложения из шага 1.
3. **Workflow.** Скопируйте содержимое `docs/relay.workflow.yml` в новый файл
   `.github/workflows/relay.yml` (Add file → Create new file → путь с двумя
   косыми чертами — GitHub сам создаст папки).
4. **IMAP.** В Яндекс Почте: Настройки → «Почтовые программы» → включите IMAP.
5. **Проверка.** Вкладка Actions → Telegram relay → Run workflow. В логе будет
   `poll: отправлено писем: N`.

## Ручной запуск без Actions (если нужно)

```bash
pip install -r requests  # см. requirements.txt
export TELEGRAM_BOT_TOKEN=... MAIL_APP_PASSWORD=...
python relay.py poll     # забрать сообщения клиентов -> письма
python relay.py answers  # ваши ответы -> клиентам
```

## Ограничения

- Задержка до 5 минут — Actions это по расписанию, не мгновенно.
- Скрипт отправляет и читает только текст. Файлы/стикеры клиентов приходят
  с пометкой «сообщение без текста» (доработка — в roadmap).
- Если письмо-ответ слишком длинное, в Telegram уйдут первые 4000 символов.
- Свежесть: offset и whitelist хранятся в файлах `state.json` и `allowed.json`,
  workflow коммитит их сам.
